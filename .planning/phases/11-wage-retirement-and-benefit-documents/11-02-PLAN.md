<objective>
Close the gap RESEARCH.md's Q3 found by reading `buildRunSnapshot` directly: the shipped Phase 7
code resolves archived and active subjects' heads/revisions into the SAME `RunSnapshot` a guest
report program's `ctx.evoList`/`evoHead`/`evoRevision`/`casRead` read from, with no archived-aware
filtering anywhere in that chain. A report program that calls `ctx.evoList('true')` today sees
archived subjects, then reads their heads/revisions/snapshot bytes exactly like any active
document's — the CONTEXT decision's claim that "archived revisions are invisible to a report
program" is true only by convention, not by construction. This is DOC-15's load-bearing
requirement: the guarantee must be enforced by a `proof`, and a proof against the CURRENT
(unfixed) code would either avoid exercising `ctx.evoList('true')` (proving nothing) or fail.

Purpose: retraction (an `archived: true` head added via `evo_add`) must actually stop a report
program from reaching the retracted document, not merely document an intention.
Output: a surgical, in-place fix to `fjs/server/fjs_run/snapshot/module.f.js`'s
`buildRunSnapshot`, plus an adversarial + control proof pair, plus a recorded, watched mutation
test (Mutation Gate M1).
