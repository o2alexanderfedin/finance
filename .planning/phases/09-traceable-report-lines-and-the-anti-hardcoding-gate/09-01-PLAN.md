<objective>
Define the report-line type (PROV-01, PROV-02): a computed monetary figure that cannot exist,
at the type level, without the sources it came from and the rule it implements. `{ value }`
without `{ sources }` must fail `tsc` — and this plan proves that assertion is load-bearing by
watching it fail, the same way Phase 6 verified its own negative type property (widen, observe
the compile error, revert), rather than assuming it holds.

Purpose: this is the type half of the anti-hardcoding gate. It makes an untraceable line
unrepresentable in the type system; the runtime half (the zero-observed-reads kill condition and
the perturbation gate) is Plans 09-03/09-04.
Output: `fjs/report/line/module.f.js` — `Source`, `ReportLine`, the compile-time assertion, and
proofs of construction and JSON round-tripping.
</objective>

    Create `fjs/report/line/module.f.js` with a module docstring naming PROV-01/PROV-02 and citing
    Phase 6's negative-type-property precedent (verified by widening, never a second tsconfig or
    `@ts-nocheck`).

    Define `Source` as a typedef: `{ readonly documentHash: string, readonly boxPath: string,
    readonly value: string }` — the (documentHash, boxPath, value) tuple as a named object (not a
    positional array) so each field greps by name. `boxPath` is a dotted string matching the
    dialect's own field name (e.g. `box1InterestIncome`). `value` is the raw value exactly as read
    at that box — the same decimal-string wire representation the dialect itself stores (EXACT-05)
    — never re-parsed or rounded in this module.

    Define `ReportLine` as a typedef: `{ readonly value: bigint, readonly sources: readonly
    [Source, ...(readonly Source[])], readonly rule: string }`. `value` is cents as `bigint` with
    NO generic type parameter (09-CONTEXT.md: this is a money line; a type variable here would only
    invite a `number` to appear downstream). `sources` is a non-empty TUPLE type (`readonly
    [Source, ...(readonly Source[])]`), never a plain `readonly Source[]` — so an empty `sources:
    []` also fails to typecheck, not merely an omitted key, satisfying PROV-02's plural "tuples".
    `rule` is a required (non-optional) string naming the form line or worksheet line implemented
    (e.g. `'1040 line 2b'`).

    Define a locally-scoped generic `Extends<A, B>` typedef using two `@template` tags:
    `[A] extends [B] ? true : false`. The tuple-wrapping (`[A] extends [B]`, not bare `A extends B`)
    prevents a union `A` from being tested member-by-member, mirroring why
    `fjs/guest/module.f.js`'s own conditional-type assertion needs the same wrapping for its own
    (different) generic. `Extends` does not exist upstream in fjs and is defined once, locally,
    here — it is the "does A structurally satisfy B" check this module's own assertion needs, which
    `Equal` alone cannot express.

    Add the PROV-01 compile-time assertion, named `_ValueAndRuleWithoutSourcesDoesNotSatisfyReportLine`:
    `Assert<Equal<Extends<{ readonly value: bigint, readonly rule: string }, ReportLine>, false>>`,
    importing `Assert` from `functionalscript/fjs/asserts/module.f.js` and `Equal` from
    `functionalscript/fjs/types/ts/module.f.js`, both as TYPE-ONLY `@import` JSDoc comments (never a
    runtime `import` statement — these types are erased), mirroring `fjs/guest/module.f.js`'s own
    import style exactly. Directly above this typedef, document: a value carrying `value` and
    `rule` but omitting `sources` must NOT satisfy `ReportLine` — traceability enforced by `tsc`,
    not by convention — and that Task 2 verifies this by deliberately widening `sources` to
    optional and watching this exact line fail to compile.

    Add a `proof` export with three leaves:
    - `fullyPopulatedLineHasAllThreeFields`: construct a `/** @type {ReportLine} */` literal —
      `value: 180300n`, `sources: [{ documentHash: 'sha256-doc1', boxPath: 'box1InterestIncome',
      value: '1234.56' }]`, `rule: '1040 line 2b'` — and `assertEq` each of the three top-level
      fields plus the one source tuple's three fields.
    - `sourcesCarriesAtLeastOneTuple`: using the same literal, assert `line.sources.length > 0`
      (the runtime witness of the type-level non-empty-tuple guarantee).
    - `wireProjectionRoundTripsThroughJson`: build the same `ReportLine`, project it to a
      JSON-safe object via `{ value: centsToString(line.value), sources: line.sources, rule:
      line.rule }` (import `centsToString` from `../../exact/module.f.js` — never
      `JSON.stringify` a `bigint` directly, per EXACT-05), `JSON.stringify` then `JSON.parse` it,
      and `assertEq` every field of the round-tripped object against the original
      (`documentHash`, `boxPath`, `value` as the decimal string `'1234.56'`, `rule`) — demonstrating
      PROV-02's "round-trips through JSON without needing a schema for paths".
