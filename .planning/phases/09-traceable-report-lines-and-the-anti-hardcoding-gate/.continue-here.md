## What the merge required that git could not do

**1. `fjs/server/fjs_run` — the pin proof.** `subjectOnlyWithoutParentsPersistsPinnedFalse`
asserted that a `subject`-only call persists `subject` on the run record. #38 deliberately changed
that: a half-supplied pin is an ordinary unpinned run, and a record saying `pinned: false` while
naming a `subject` names a subject the run was never pinned to. **#38 is right.** The assertion now
pins the corrected behaviour and still kills the `&&`→`||` mutation on its own.

**2 and 3. Two refusal proofs had been silently weakened.** The feedback pass rewrote
`fjs/tax/table`'s $100,000 refusal and `fjs/server/fjs_run/snapshot`'s absent-hash refusal as bare
`throw: { ... }` leaves, dropping their assertions, on the stated grounds that *"reading a thrown
value means catching it, and a `.f.js` module may not."*

**That premise is false.** `fjs/exec/module.f.js` catches in shipped production code, and both
proofs pass under `npm test`. The `throw:` form is strictly weaker — it passes for *any* throw.
Mutating the tax-table refusal's `<` to `<=` still throws at exactly $100,000.00, just via the
unrelated "outside every stored band region" path. Asserting **what** was thrown rather than
**that** something was is the exact gap the mutation sweep found. Both are restored, each carrying
a `MERGE NOTE` explaining why it must not be re-reverted.

## The new rule this merge earned

The snapshot regression **carried no textual conflict**. Git merged it silently, the suite was
green, and nothing flagged it.

> **A clean merge with a green suite can still have dropped coverage.**

The check that caught it, and that this kind of merge now warrants:

```
# 1. proof-leaf sets of BOTH parents must be subsets of the result
node --test 2>&1 | grep -o '^✔ import("\./fjs/[^ ]*' | sort -u   # in each of: parent A, parent B, result
comm -23 parentA.txt result.txt        # must be empty, or every line explained
comm -23 parentB.txt result.txt

# 2. a name-set diff is NOT sufficient — a leaf can keep its name and lose its assertions
#    so also compare, per changed file:
grep -cE '\bassert(Eq|NotNullish)?\(' <file>   # before vs after; a drop is a regression
```

Step 1 found the dropped leaf. Step 2 is what would have found it had the leaf kept its name.

## Still true, and still the most valuable thing here

> **A red mutation means the tests and the code AGREE. It does not mean the code is right.**

The sweep tested `String(value)` → `JSON.stringify(value)`, saw three tests fail, and recorded it
CAUGHT. The proofs used fixtures returning JSON *strings*, so `stringify` double-encoded and broke
them — the tests were pinning a real bug. That bug is now fixed, by #38's `withResultText`, which
came in with this merge.

## Standing hazards (unchanged)

- **Never gate on `npm test`'s total.** It includes ~2,100 vendored submodule proofs. Use
  `node --test 2>&1 | grep -c '^✔ import("./fjs/'`.
- **`node --test <some .f.js file>` is a documented fake pass.** Only root discovery registers
  proofs. (`fjs-run-integration.test.js` is an ordinary `node:test` file and is exempt.)
- **Never `cd` into `./functionalscript`** — it is a submodule and a bare `cd` persists across later
  commands in this harness. Use `git -C` and absolute paths. It bit this session twice more.
- **`npm test --prefix <dir>` does NOT run that directory's tests.** It sets the package location
  but runs the script in the current cwd. It reported a merge candidate green when it had in fact
  re-run a different tree; the real result was one failure. Use `( cd <dir> && npm test )`.
