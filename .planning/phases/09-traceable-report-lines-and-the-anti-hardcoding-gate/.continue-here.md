### 2. A real bug ships here, and this branch's tests protect it

`fjs/server/fjs_run/module.f.js:275` — `String(outcome.value)`.

The guest ABI is `Report<T>` with `T` unconstrained. A structured result becomes `'[object Object]'`,
which is then hashed, stored, and attested to by the run record's `resultHash`. The answer destroyed,
with provenance certifying the destruction.

**Do not fix it here.** PR #38 already fixes it properly (`withResultText`: strings pass through
byte-for-byte, other JSON values via `fjs/media/json`'s `stringify`, non-representable values become
an error outcome that still gets a run record). A third implementation would conflict.

**The trap worth internalising:** the mutation sweep tested exactly this — `String(value)` →
`JSON.stringify(value)` — saw three tests fail, and recorded it **CAUGHT**. The proofs use fixtures
that return JSON *strings*, so `stringify` double-encodes and breaks them. The tests were pinning
the bug and the sweep read that as coverage working.

> **A red mutation means the tests and the code AGREE. It does not mean the code is right.**

The parallel session found this by review, not mutation. Different method, caught what mine couldn't.

### 4. `node --test <some .f.js file>` is a documented fake pass

Emergent Testing only registers proofs reachable from root `all.test.js`. Only `npm test` counts.
(`fjs-run-integration.test.js` is an ordinary `node:test` file and is exempt.)

### 5. Never `cd` into `./functionalscript`

It is a submodule; a `cd` persists across later commands in this harness and silently redirects
everything after it into the wrong repository. This produced a false "the build is broken" report
once, and it bit me again during the sweep. Use absolute paths or `git -C`.
