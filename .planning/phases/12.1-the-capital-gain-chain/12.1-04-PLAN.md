Form 1040 wiring, and Task 2 is the scope-table + branch-2a change — the reverse of the
intuitive order.**

This ordering is not merely "safe by omission" — it is provably correct at every intermediate
commit, for two independent reasons:
1. **The six kinds stay in `unmodeledKindRefusals` throughout Task 1.** Any taxpayer who
   DECLARES `qualifiedDividends`, `ordinaryDividends`, `capitalGainDistributions`, or
   `capitalGainsOrLosses` is refused by `classifyScope` — which runs BEFORE `computeForm1040`
   is ever called — before Task 1's new wiring code is reached at all. Task 1's new code is
   real but genuinely unreachable for exactly the declarations that would otherwise see a
   confident zero.
2. **A NON-declaring taxpayer with real 1099-DIV/1099-B documents is not the hazard.** Task 1's
   `line3a`/`line3b` read directly from stored documents, unconditionally — the SAME pattern
   `line1a` (wages) and `line2a`/`line2b` (interest) already use, with no declaration gate,
   because a MODELED line's job is to report what the documents say, and `declaredKinds` exists
   to gate REFUSALS for kinds the engine cannot yet compute, not to gate individual already-
   computable lines. A taxpayer who never declares `qualifiedDividends` but holds a real
   1099-DIV gets their REAL dividend figure, not a wrong one — strictly more correct than
   today's unconditional `declaredZero`, never less. **A genuinely pleasant consequence**: since
   `dispatchLine16`'s branches 2c/2d (qualified dividends without Schedule D; capital gain
   distributions without Schedule D) already compute via the existing, unmodified `qdcgt`
   worksheet, Task 1 alone makes a real subset of returns (dividend income with no Schedule D
   activity) compute a genuinely correct Form 1040 line 16 — before Task 2 ever runs. Only
   returns that need the Schedule D Tax Worksheet specifically (declared `capitalGainsOrLosses`,
   or `unrecaptured1250Gain`/`collectibles28RateGain` present) stay refused until Task 2, and
   they stay refused via the SAME `classifyScope` mechanism that refuses them today — never a
   wrong number.

Purpose: this is the phase's central deliverable — the moment `dispatchLine16`'s
`scheduleDTaxWorksheet` branch stops refusing and starts computing, and the moment dividend
