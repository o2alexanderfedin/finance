### `fjs/form8949/module.f.js` (NEW)

**Analog:** `fjs/schedule/b/module.f.js` (537 lines, Phase 12 — the most recent schedule
module, explicitly named as the precedent by CONTEXT.md Decision 2.1)

**What to copy — the module docstring shape** (`fjs/schedule/b/module.f.js:1-66`):
- Cite the fetched IRS source PDF and its printed revision date in the opening comment
  block, exactly as Schedule B does (`fjs/schedule/b/module.f.js:6-8`).

  NOTHING at runtime from `fjs/tax/`, `fjs/return/scope`, or `fjs/form1040/` — copy this

- State every deliberate scope boundary as its own docstring paragraph headed "## ..." —
  Schedule B does this for its Form 8815 boundary (`fjs/schedule/b/module.f.js:23-35`);
  Form 8949 needs the equivalent for categories C/F (no-1099-B transactions, deferred)
  and for boxes 1f/1g (wash sale / accrued market discount, Decision 1.4).

**What to copy — the aggregation idiom** (`fjs/schedule/b/module.f.js:98-158`):
```js
const sumBoxOverDocuments = documents => boxPath => read => {
    const sources = documents.flatMap(document => {
        const printed = read(document.value)
        return printed === undefined
            ? []
            : [{ documentHash: document.documentHash, boxPath, value: printed }]
    })
    return {
        value: sources.reduce((total, source) => total + centsFromString(source.value), 0n),
        sources,
    }
}
const addBoxSums = a => b => ({ value: a.value + b.value, sources: [...a.sources, ...b.sources] })
const profileDeclaredZeroLine = profile => rule => ({
    value: 0n,
    sources: [{ documentHash: profile.documentHash, boxPath: 'declaredKinds',
        value: JSON.stringify(profile.value.declaredKinds) }],
    rule,
})
const documentLine = profile => rule => sum => {
    const [first, ...rest] = sum.sources
    return first === undefined ? profileDeclaredZeroLine(profile)(rule) : { value: sum.value, sources: [first, ...rest], rule }
}
```
Reimplement these four locally and PRIVATELY, not imported from `fjs/form1040/core` or
`fjs/schedule/b` — the docstring at `fjs/schedule/b/module.f.js:58-63` states this is the
established "reimplement an idiom you cannot import" precedent (also cited from
`fjs/server/finance_documents_list`). Category totals aggregate over `Stored<OneZeroNineNineB>[]`
the same shape `ScheduleBInputs` uses (`fjs/schedule/b/module.f.js:81-95`).

**No analog for the category derivation itself.** CONTEXT.md 2.4 requires deriving A/B/D/E
from `box12BasisReportedToIrs × (box2ShortTermGainOrLoss | box2LongTermGainOrLoss)`, then
asserting agreement with `applicableCheckboxOnForm8949` when present — never trusting the
payer letter. Nothing in this repo does a "derive-then-cross-check-against-a-stored-hint"
pattern; the closest structural precedent is `fjs/return/scope`'s partition-by-construction
idiom (a value must land in exactly one of two exhaustive buckets), but that is a `tsc`-level
partition over a closed kind vocabulary, not a runtime cross-check against document data.
**Design this fresh**, following RESEARCH.md's category table (`i8949.pdf` pp.3-4) and the
"Undecided by any dialect field" fallback (neither/both of `box2ShortTermGainOrLoss` /
`box2LongTermGainOrLoss` true) — RESEARCH.md recommends a computation-level refusal there,
shaped like Decision 2.6's absent-basis refusal (see `fjs/tax/line16/module.f.js` pattern
below).

**Absent-basis refusal (Decision 2.6) — shape to copy, not an existing document-tier
refusal.** This is the module's other genuinely novel piece. Mirror `fjs/return/scope`'s
`ScopeError` extraction device (`fjs/return/scope/module.f.js:233-244`):
```js
/** @typedef {Extract<ScopeOutcome, { readonly kind: 'error' }>} ScopeError */
```
and `fjs/form1040/core`'s threading of `line16Outcome`'s error arm
(`fjs/form1040/core/module.f.js:779-785`):
```js
if (line16Outcome.kind === 'error') {
    return { kind: 'error', message: line16Outcome.message, unmodeled: line16Outcome.unmodeled }
}
```
Form 8949's own `{ kind: 'error', ... }` result is NOT built by `scopeRefusal` (this is a
document-data-sufficiency problem, not a declared-kind scope problem — CONTEXT.md 2.6
explicitly forbids adding a 51st kind), so it needs its own small tagged-union type, shaped
the same way, threaded up through `fjs/schedule/d` and into `fjs/form1040/core` exactly as
`Line16Outcome`'s error arm already threads.
