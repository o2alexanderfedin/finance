## Mutation Gate M2 — Watched Failing (12.1-VALIDATION.md row M2)

**Mutation applied** (Task 2, in `fjs/form8949/module.f.js`'s `categorize` function): swapped the letter outputs between the short-term and long-term branches, so a short-term-flagged document derives a long-term category and vice versa:

```js
// Before (correct):
if (box.box2ShortTermGainOrLoss === true) {
    return box.box12BasisReportedToIrs === true ? 'A' : 'B'
}
if (box.box2LongTermGainOrLoss === true) {
    return box.box12BasisReportedToIrs === true ? 'D' : 'E'
}

// After (mutated):
if (box.box2ShortTermGainOrLoss === true) {
    return box.box12BasisReportedToIrs === true ? 'D' : 'E'
}
if (box.box2LongTermGainOrLoss === true) {
    return box.box12BasisReportedToIrs === true ? 'A' : 'B'
}
```

Applied against this plan's own mixed-gain/loss fixture: a $6,000.00 short-term GAIN (`box2ShortTermGainOrLoss: true`, `box12BasisReportedToIrs: true`) and a $2,000.00 long-term LOSS (`box2LongTermGainOrLoss: true`, `box12BasisReportedToIrs: true`), net $4,000.00 gain.

**Which leaf reddened:** `import("./fjs/schedule/d/module.f.js").proof.shortTermAndLongTermKeptIndependentlyObservable.sixThousandShortTermGainAndTwoThousandLongTermLossNetFourThousand()` — the exact leaf this plan's Task 1 wrote for this purpose. 12 other leaves also reddened (`fjs/form8949`'s own `categorization`/`absentBasisRefusal`/`crossCheckAgainstPayerPrintedLetter` proofs, and this module's own `zeroNetYearRoutesExactlyZero` and `cleanGainInBothPartsRoutesLine16Exactly`) — the mutation's blast radius is wide because it inverts the WHOLE category derivation, not just this one fixture's shape; only the one named leaf is Mutation Gate M2's specific target.

**Which assertion reddened:** `assertEq(result.line7, 600000n, 'ST: $9,000.00 - $3,000.00 = $6,000.00 gain')` — failure output:

```
[ -200000n, 600000n, 'ST: $9,000.00 - $3,000.00 = $6,000.00 gain' ]
```

`assertEq` throws on the first mismatch, so the leaf's later `line15` assertion never ran under the test harness. A direct invocation of `scheduleD` with the identical fixture and the mutation in place (before reverting) recorded the full picture:

```json
{ "line7": "-200000n", "line15": "600000n", "line16": "400000n", "line7aCapitalGainOrLoss": "400000n" }
```

**Both `line7` and `line15` reddened** — the $6,000.00 short-term gain and the $2,000.00 long-term loss traded places between Schedule D's two Parts (the short-term-flagged document landed in Category D, contributing its $6,000.00 gain to `line15`; the long-term-flagged document landed in Category A, contributing its -$2,000.00 to `line7`) — exactly the wrong shape Mutation Gate M2 exists to catch.

**The equivalent-mutant trap, demonstrated explicitly:** `line16` computed to `400000n` both BEFORE and AFTER the mutation (`600000n + -200000n = 400000n`, and `-200000n + 600000n = 400000n` — commutative addition erases which side each number came from). A proof asserting `line16` alone — which this plan's own `shortTermAndLongTermKeptIndependentlyObservable` leaf deliberately does NOT do — would have stayed green under this mutation, confirmed by direct invocation showing the identical `400000n` on both sides. Only asserting `line7` AND `line15` separately catches it, which is exactly why Task 1's fixture was built to name both.
