<objective>
Build the `finance_schema(dialect)` MCP tool (MCP-06): given a dialect tag, return that
dialect's own RTTI schema serialized as JSON Schema via fjs's existing `toJsonSchema` — so an
agent reads field names instead of guessing them, which is the precondition for Success
Criterion 1's "authors a program against `vnd.fjs.1099int`'s field names."

Purpose: this is the first half of the Week-1 finish line (`finance_schema` -> author -> store
-> `fjs_run`) and is fully independent of every other mechanism this phase builds — no CAS
write, no interpreter, no materialization.
Output: `fjs/server/finance_schema/module.f.js` exporting `financeSchemaTool`, a `ToolEntry`
ready to be concatenated into `financeMcpHandlers` (wired in Plan 08).
</objective>

      (or equivalent — an actionable message naming the unknown dialect and the known set,
      mirroring `fjs/exec`'s own `refusalMessage` convention of naming both).

      (already wired upstream) rejects a call missing `dialect` before this handler ever runs.
