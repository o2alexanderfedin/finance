<objective>
Build the size-guarded response envelope (EXEC-11): a parameterized, cheaply-testable function
that decides whether a result's text can be inlined, truncated to a preview, or must be replaced
entirely by the message `result too large; stored at <hash>` — proven WITHOUT ever allocating a
real >128 KiB string, and proven to run BEFORE the transport layer, not merely to produce the
right-looking text.

Purpose: the stdio line cap is 128 KiB (`fjs/types/bigint`'s `maxLength = 0x100000n` bits, traced
during research) and overflow degrades to a silent `-32603` with no indication size was the
problem. This plan is fully self-contained — no CAS, no interpreter, no materialization — so it
can be proven in isolation and reused unchanged by Plan 06.
Output: `fjs/server/response/module.f.js` exporting `sizeGuard`, `previewBytes` (8192),
`guardBytes` (65536).
</objective>

  <behavior>
    - `sizeGuard = guardBytes => previewBytes => (content, hash) => { preview: string, truncated: boolean }`
      (byte length measured on the UTF-8 encoding of `content`, not `content.length`'s UTF-16
      code-unit count — use `fjs/text`'s `tryUtf8`/`utf8` or `Buffer.byteLength` semantics
      consistently with how the rest of this codebase measures byte size; check
      `fjs/types/bit_vec`'s `length` convention used elsewhere in this repo for the 128 KiB
      cap and stay consistent).
    - If `content`'s byte length is `<= previewBytes`: `{ preview: content, truncated: false }`.
    - If `previewBytes < length <= guardBytes`: `{ preview: content's first previewBytes bytes, truncated: true }`.
    - If `length > guardBytes`: `{ preview: \`result too large; stored at ${hash}\`, truncated: true }`
      — the exact string from Success Criterion 5, verbatim, with the hash interpolated.
    - `previewBytes = 8192` (8 KiB), `guardBytes = 65536` (64 KiB) — both exported as named
      constants, both well clear of the 128 KiB stdio cap traced in `fjs/types/bigint`'s
      `maxLength = 0x100000n` (131,072 bytes).
  </behavior>
  <action>

    `guardBytes` as the module's two named constants. Write a header explaining the two
    thresholds exist so a JSON-RPC envelope wrapped around the payload never approaches the 128
    KiB stdio cap — a single threshold set at the cap itself leaves no headroom, which is
    exactly how the silent `-32603` is reached (cite this reasoning, matching 07-CONTEXT.md's
    own wording).
  </action>
