<objective>
Close TAX-05 and TAX-16 together: Form 1040 lines 16 through 37, and the entry point that refuses
the **whole report** when the declared return reaches outside what the engine models.

10-CONTEXT.md Decision 2, restated because it governs the shape of everything here: an unmodeled
input makes the entire report an error result naming what is unmodeled. A partial 1040 is never
returned, so there is no way to mistake one for a complete return. The rejected alternative — a
per-line refusal inside a returned report — is more informative for debugging and ships a document
that looks like a 1040 while being incomplete, which is the exact failure mode TAX-16 exists to
prevent.

The declared profile is 65+ with dependents, and that forces two refusals that are the phase's
honest acceptance rather than a gap: **line 13b** (Schedule 1-A's enhanced deduction for seniors,
TAX-09, Phase 13) and **line 19** (Schedule 8812, TAX-12, Phase 13). ROADMAP already states the
consequence — "a 65+ TY2025 return omitting Schedule 1-A is structurally wrong, not merely
incomplete" — so Phase 10's acceptance is that these produce loud, named refusals, not that the
return computes.

Purpose: this is the phase's shippable surface and the last plan in the wave order.
Output: `form1040Report` in `fjs/form1040/core/module.f.js`.
