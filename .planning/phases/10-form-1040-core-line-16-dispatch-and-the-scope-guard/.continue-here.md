## The one open decision — needs Sergey

**Whether the engine repository and the demo become public. One decision, not two.**

Not a plumbing problem, and no hosting arrangement routes around it:

> **A demo that runs the real engine in a public page publishes the real engine.**

The browser must download `fjs/**` to execute it — 37 `.f.js` files, ~950 KB, including
the design-rationale comments (`SEC-*` identifiers, REQUIREMENTS references, phase
context, the accepted-risk note in `fjs/guest/materialize`). A separate public repo does
not help: the same bytes must reach the browser. A cross-repo read token stored in a
public repo is strictly worse — exfiltratable by any workflow edit, and it does not
prevent the disclosure it appears to protect.

**Second consequence, easy to miss:** every `source ↗` / `proof ↗` link and the build
badge point at `github.com/fjs-dev/finance`, which is **private**. They resolve for org
members — so a laptop demo is fine — and 404 for everyone else. Publishing the page
without resolving repo visibility produces a public page whose central claim is broken.

`.github/workflows/pages.yml` exists, carries that warning in a box at the top of the
file, is `workflow_dispatch` only, and **has never been run**.

## What this session cost, and the one lesson worth carrying

Phase 10's lesson was *verification machinery fails silently, in the direction of looking
successful*. This session produced the environment-and-process twin of it. **Four of the
nine commits exist only because something was checked rather than assumed**, and in every
case the symptom pointed somewhere other than the cause:

- **Stale `node_modules`.** Two of three checkouts ran `functionalscript@0.41.0` against a
  lockfile pinning `0.43.0`. Symptom: sixteen `tsc` errors *inside `fjs/**`* that are not
  defects in `fjs/**`, and a proof count ten short — because a module that fails to import
  never registers its proofs. Every symptom accused the engine. None of it was the engine.
- **`git add` on the uninitialized submodule.** It silently reverts a staged gitlink to
  HEAD's value, so a commit came out without the change its own message described. I had
  checked `git diff --cached` *before* committing instead of `git ls-tree HEAD` *after* —
  the pre-commit check passes right up until the commit that drops it.
- **`git update-index --cacheinfo` accepts a SHA that does not exist**, silently.
- **A `#L` anchor that still resolves but lands in the wrong place.** Re-pinning the demo,
  a path-exists sweep would have passed while an anchor pointed at the wrong line — which
  is worse than a 404 because nothing looks broken.

> **The check that would have caught it and the check you ran are rarely the same check.**

All four are now in `AGENTS.md` (+47 lines this session) beside their siblings.

**Not one wrong number reached a page.** Every figure in `CHANGELOG.md` — 6 tools, 5
dialects, 6 modeled, 44 refused, 56 lines, 4 commands, 492 proofs — was re-derived from
the code while writing it. The demo's regression pair recomputes live and prints a
per-case verdict; step 1 re-hashes the JSON it printed and shouts on mismatch.

## Standing hazards (all still live)

- **Never gate on `npm test`'s total.** It includes the vendored submodule proofs and so
  depends on whether `functionalscript/` is checked out — the SAME commit reports 494 in a
  worktree without it and 2730 in one with it, both correct. Use
  `node --test 2>&1 | grep -c '^✔ import("./fjs/'`.
- **Each worktree has its own `node_modules`.** `npm ci` in one does nothing for the
  others, and nothing announces the difference.
- **`node --test <some .f.js file>` is a documented fake pass.** Only root discovery
  registers proofs.
- **`npm test --prefix <dir>` does NOT run that directory's tests.** Use
  `( cd <dir> && npm test )` in a subshell.
- **Never `cd` into `./functionalscript`** — a submodule, and a bare `cd` persists. Note
  it IS checked out in the main checkout now (at `cc93a3ca` = 0.43.1) and is NOT in the
  two worktrees; that asymmetry is what makes the proof totals differ.
- **Sergey's `wtf` and `revert-14-feature/planning-requirements-roadmap` stay untouched.**
  `revert-14…` deletes 4,007 lines of planning docs and its PR was closed unmerged.
