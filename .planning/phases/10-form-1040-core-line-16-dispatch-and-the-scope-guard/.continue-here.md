### Hosting is deferred, and not for a plumbing reason

The first showcase is presented from a laptop. Whether any of this becomes public is an
open decision to be taken with Sergey. The blocker:

> **A demo that runs the real engine in a public page publishes the real engine.**

The browser must download `fjs/**` to execute it — 37 `.f.js` files, ~950 KB, including
the design-rationale comments. No hosting arrangement avoids that: not a separate public
repo (the same bytes must reach the browser), not a vendored snapshot, and certainly not
a cross-repo read token stored in a public repo, which is exfiltratable by any workflow
edit and does not prevent the disclosure it appears to protect.

**A second consequence:** every `source ↗` / `proof ↗` link and the build badge point at
`github.com/fjs-dev/finance`, which is **private**. They resolve for org members — so the
laptop demo is fine — and 404 for everyone else. Repo visibility and demo hosting are one
decision, not two.

`.github/workflows/pages.yml` exists, carries that warning in a box at the top of the
file, is `workflow_dispatch` only, and **has never been run**.

**Do not re-litigate these three, they are settled and the reasoning is in the spec:**

1. **The demo imports the REAL engine as ES modules.** Not a mock, not a recording. Every
   module under `fjs/` is pure — the only `node:` strings in the tree are inside proof
   fixtures asserting a guest importing `node:fs` is refused — and `functionalscript`'s
   `virtual` fs has no `node:` imports either. Bare specifiers resolve via a native
   `<script type="importmap">`. Zero dependencies, zero build step.
2. **WASM with a POSIX filesystem is the WRONG answer** to the `import()` question, and not
   only because it is a forbidden dependency. An engine inside a WASM jail tells a
   stakeholder the *jail* is what makes it safe, when the claim is that the frozen effect
   vocabulary is. It is also unnecessary: **the guest never calls `import()`, it emits an
   import effect**, and the host map decides what that means — a `blob:` URL satisfies it
   in about ten lines.
3. **The sandbox claim on step 7 is narrower than "it cannot reach the network."** See the
   boundaries below. This nearly shipped as an overclaim.

### The three boundaries the demo states out loud

A stakeholder will find these. Much better they hear them from us.

- **The engine is proven; the app is not wired end-to-end.** `form1040Report` has no
  production caller — no server path produces a 1040 today. Phase 14 owns that.
- **The Schedule D branch refuses by design** — correctly *selected*, then refuses naming
  unrecaptured §1250 gain and 28%-rate gain. Phase 12 owns the computation.
- **Guest bodies run with host privileges.** What is real and provable: a guest requesting
  `fetch` *through the effect system* is refused by name, and a disallowed import specifier
  is refused *before the module body executes*. What is not defended: a guest calling
  `globalThis.fetch(...)` directly. This is a recorded accepted risk, stated in
  `fjs/guest/materialize`'s own header. **I sketched step 7 as "watch it refuse network
  access", checked before writing the spec, and found the codebase honest about not having
  it.** Discovering that in the room would have been expensive.

## What Phase 10 cost, and the one lesson worth carrying

Ten plans, six waves, 318 → 492 project-local proofs. The plan set was returned **BLOCKER**
by `gsd-plan-checker` (four blockers, ten warnings), revised, re-checked, then executed.

**Fourteen plan defects were found. Not one was a wrong tax number.** Research, planning,
two review rounds and six executors independently reproduced every figure — the QDCGT pair,
the twenty Tax Computation Worksheet rows, the nineteen chart combinations — and none needed
correcting. Every defect was in **the machinery that proves the arithmetic**:

- mutations that could not compile (`noUnusedLocals` fires when removing an expression
  orphans its binding — four instances)
- mutations a neighbouring operation absorbed, so they could not redden at any input
- mutations mandated at gates whose target leaves did not exist yet
- acceptance tallies that said "four mutations" for a five-mutation task — and in three
  cases the uncounted one was **the mutation closing a blocker**
- a type guard that only worked against fresh object literals, so a spread or an
  intermediate variable walked straight past it

> **Verification machinery fails silently, and it fails in the direction of looking
> successful.**

Four new `AGENTS.md` sections came out of this phase. Read them before writing plans:
the three mutation failure modes, the concurrency hazard, and a **fourth** instance of this
project's signature defect — a proof iterating `Object.keys()` of the code under test, which
could never notice an entry being deleted.

**The single sharpest artifact:** swapping the line-16 dispatcher's condition order returns
**identical cents** on every ordinary return. Only the method tag catches it. A suite built
from realistic test returns would have shipped it with a full green board.

## Standing hazards (unchanged, all still live)

- **Never gate on `npm test`'s total** — it includes ~2,100 vendored submodule proofs. Use
  `node --test 2>&1 | grep -c '^✔ import("./fjs/'`.
- **`node --test <some .f.js file>` is a documented fake pass.** Only root discovery
  registers proofs.
- **`npm test --prefix <dir>` does NOT run that directory's tests** — it sets the package
  location but runs in the current cwd. It reported a merge candidate green while re-running
  a different tree. Use `( cd <dir> && npm test )`, in a subshell.
- **Never `cd` into `./functionalscript`** — a submodule, and a bare `cd` persists across
  later commands. Use `git -C` and absolute paths.
- **Concurrent executors corrupt mutation observations** — `tsc` is repo-wide, so a
  sibling's half-finished file reddens your suite for reasons unrelated to your mutation.
  A red you did not cause confirms a mutation that never worked. Snapshot with
  `git archive HEAD | tar -x` (not `cp -a`, which shares the real `.git`).
