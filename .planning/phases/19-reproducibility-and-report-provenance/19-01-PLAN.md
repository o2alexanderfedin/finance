paramSetHash's call chain (all four functions already ship in the pinned `functionalscript`
version; NONE has a call site anywhere in this repo's own `fjs/` today):

```
tryUtf8(text: string) => Uint8Array | null                         -- functionalscript/fjs/text/module.f.js
computeSync(sha256)(list: Vec[]) => Vec                             -- functionalscript/fjs/crypto/sha2/module.f.js
vecToCBase32(vec: Vec) => string                                    -- functionalscript/fjs/basen/cbase32/module.f.js
jsonText (this repo's own binding, = stringify from fjs/media/json, bound to source-key-order) -- fjs/json/module.f.js
```

Composition: `vecToCBase32(computeSync(sha256)([tryUtf8(jsonText(taxParamSet))]))`, with an
`assert(bytes !== null, ...)` between the `tryUtf8` call and the hash — mirrors
`fjs/report/amend/module.f.js`'s own `seedText` helper and `fjs/server/fjs_run/module.f.js`'s
`writeTextToCas`, both of which do `tryUtf8` then hash; the only difference is this function
stops before any `cas.write` — nothing needs to be retrievable by this hash, only stable.

From `fjs/report/amend/module.f.js` (the Q2 precedent this module's docstring must restate, not
contradict — lines 14-23 of that file):
"The parameter-set guard is `programHash` equality, not a new field. Guest programs cannot
`import` anything and `guestCtx` exposes no tax-parameter lookup, so every dollar figure a
stored program consults is a literal baked into that program's own source text — which the CAS
hash already covers." `paramSetHash` does NOT contradict this for the guest-program path; it
names a DIFFERENT fact — the parameter set the HOST ENGINE (`fjs/form1040/core`'s
`form1040Report`) was handed when a report was computed.

From `fjs/report/guard/module.f.js` (the predicate-shape and proof-style precedent):
```
export const classifyRunOutcome = literalCount => (value, reads) => reads.length === 0
    ? { kind: 'error', ... }
    : { kind: 'ok', ... }
```
one exported, hand-named, pure function; both arms of any predicate get their OWN separately
named proof leaf, never one combined leaf.

From `fjs/run/module.f.js` (what the acceptance predicate reads, and what it does NOT need to
re-derive): `runSchema`'s `checkReferences` (lines 151-183 of that file) already enforces
"pinned must agree with subject/parents, both present or both absent" in both directions. The
predicate below only reads `run.pinned` — it must NOT re-implement that both-or-neither check.
