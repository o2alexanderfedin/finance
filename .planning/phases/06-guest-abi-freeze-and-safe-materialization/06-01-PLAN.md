<objective>
Freeze the guest ABI. Promote `fjs/exec`'s four test-fixture operations into a real, exported
`CasOp` vocabulary; define the `report` entry point; and put the whitelist **in the type** so
`tsc` rejects a network-reaching program before it can ever be stored.
</objective>

<tasks>

<task type="auto" tdd="true">
  <name>Task 1: fjs/guest/module.f.js — the frozen vocabulary and entry point</name>
  <files>fjs/guest/module.f.js</files>
  <behavior>
    - `CasOp` is the union of exactly `casRead`, `evoList`, `evoHead`, `evoRevision`, each
      `(a: string) => string`. This matches `fjs/exec`'s fixture shape exactly, so `interpret`
      dispatches them unchanged — JSON on the wire, because fjs's JSON `Primitive` has no bigint
      (Phase 4's finding) and a guest result must cross JSON-RPC.
    - `guestCtx` is a null-prototyped record of the four constructors, each typed
      `(a: string) => Effect<CasOp, string>`. It is the ONLY vocabulary a stored program has.
    - `casOpNames` is the frozen ordered name list, matching `Object.keys(guestCtx)` order.
    - `Report<T>` is `(ctx: GuestCtx) => (args: readonly string[]) => Effect<CasOp, T>`.
  </behavior>
  <action>
    Narrow `do_` per command exactly as `fjs/exec` does (`do_('casRead')` alone under-constrains
    `O` to bare `Operation`; the `@type` annotation is what pins it). Null-prototype `guestCtx`
    as defence in depth, citing that `match`'s own-property `at` lookup is the actual mechanism.

    **Criterion 1 without a subprocess.** Do not spawn `tsc`. Express the negative as a
    conditional type evaluated inside the normal build:

    ```js
    /** @template A, @template B @typedef {[A] extends [B] ? true : false} Extends */
    /** @type {Extends<Fetch, CasOp> extends false ? true : never} */
    const fetchIsNotPermitted = true
    ```

    If `Fetch` ever became assignable to `CasOp`, the annotation resolves to `never`, `= true`
    stops compiling, and `npm test` fails at the `tsc` step. This is strictly better than a
    negative-compile harness: no second tsconfig, no `@ts-nocheck`, no third root-level impure
    file, and it is checked on EVERY run rather than only when a harness is invoked.
    `noUnusedLocals` is on, so surface the assertions through the `proof` export.

    Cover all four of `Fetch`, `Fs`, `Http`, `Forever`, plus `WriteBytes`/`Rm` from
    `FileCasOperation` — the roadmap names the first four, but the store-mutating ops are the
    ones an over-eager widening would actually reach for.
  </action>
  <verify>
    <automated>set -o pipefail; npm test 2>&1 | grep -E "error TS|^ℹ (tests|pass|fail)"</automated>
  </verify>
  <acceptance_criteria>
    - Proof leaves: the four constructors dispatch through `fjs/exec`'s `interpret` against a
      matching map; `casOpNames` matches `Object.keys(guestCtx)`; `guestCtx` has a null prototype.
    - The negative assertions compile, and **flipping one is proven to break the build** — change
      an `Extends<Fetch, CasOp>` assertion to assert the opposite and confirm `tsc` errors.
    - No import of `fjs/document`, `fjs/server`, or anything CAS-write-shaped.
  </acceptance_criteria>
</task>
