From `functionalscript/fjs/mcp/module.f.js` — the exact pattern to mirror (fjs's own
`casMcpServer`), reused verbatim except for the config and (implicitly) the store path:

```
export const casMcpHandlers = home => cacheKey => fromRegistry([
    ...casToolRegistry(home)(cacheKey),
    ...evoToolRegistry(evo(fileCas(sha256)(home))(cacheKey)),
])

export const casConfig = {
    serverInfo: { name: 'functionalscript-cas', version: '0.30.0' },
    capabilities: { tools: {} },
    protocolVersion: '2024-11-05',
}

export const casMcpServer = home => step(
    initEvo(fileCas(sha256)(home)),
    cacheKey => step(
        create(uninitializedState),
        sessionKey => stdioTransport(mcpStep(casConfig)(casMcpHandlers(home)(cacheKey))(sessionKey)),
    ),
)

export const proof = { casMcpServer: () => { casMcpServer('/'); } }
```

From `functionalscript/fjs/protocol/mcp/module.f.d.ts`:
- `export type McpConfig = { readonly serverInfo: Implementation; readonly capabilities: ServerCapabilities; readonly protocolVersion: string }`
- `export type Implementation = { readonly name: string; readonly version: string }`
- `export declare const mcpStep: (config: McpConfig) => <O>(handlers: McpHandlers<O>) => (stateKey: Key<McpSessionState>) => (value: Unknown) => Effect<MemOp | O, Response | null>`
- `export declare const fromRegistry: <O>(registry: readonly ToolEntry<O>[]) => McpHandlers<O>`
- `export declare const uninitializedState: McpSessionState`
- **`mcpStep`'s `initialize` handler validates the client's params and unconditionally returns the configured `protocolVersion` — it does not compare against, or echo, what the client sent.** This is the phase's one real risk; do not wrap or replace `mcpStep` to fix it (out of scope this plan — recorded and empirically proven in Plan 02).

From `functionalscript/fjs/protocol/mcp/stdio/module.f.d.ts`:
- `export declare const stdioTransport: <O>(handler: Step<O>) => Effect<Read | Write | O, void>` — drives read→parse→dispatch→write until stdin EOF, then resolves `void`.

From `functionalscript/fjs/cas/module.f.d.ts`:
- `export declare const fileCas: (sha2: Sha2) => (path: string) => FileCas` — internally appends `.cas` to `path` itself (`storePrefix = join(path, '.cas')`). Passing the **repo root** as `path` therefore stores content under `<repo-root>/.cas/`, mirroring `~/.cas` but project-local.

From `functionalscript/fjs/cas/evo/module.f.d.ts`:
- `export declare const initEvo: <O>(cas: Cas<O>) => Effect<O | MemOp, Key<Cache>>`
- `export declare const evo: ...` (builds the `Evo<O>` API over a `Cas<O>` + cache key)

From `functionalscript/fjs/mcp/cas/module.f.d.ts` / `functionalscript/fjs/mcp/evo/module.f.d.ts`:
- `export declare const casToolRegistry: (home: string) => (cacheKey: Key<Cache>) => readonly ToolEntry<FileCasOperation | MemOp>[]`
- `export declare const evoToolRegistry: <O>(e: Evo<O>) => readonly ToolEntry<O | MemOp>[]`
- Tool names produced: `cas_add`, `cas_get`, `cas_list`, `evo_list`, `evo_head`, `evo_revision`, `evo_add`.

From `functionalscript/fjs/effects/node/module.f.d.ts`:
- `export type NodeProgramOptions = { readonly args: readonly string[]; readonly env: Env; readonly home: string; ... }` — **`options.home` is the OS home directory (`os.homedir()`), NOT a project path.** Do not use it as the CAS home; a `.f.js` file cannot call `process.cwd()` (impure), so the CAS home must arrive as an explicit CLI arg (`options.args[0]`) supplied by whatever launches the process — Plan 03's `claude mcp add` registration bakes in the absolute repo-root path.
- `export type NodeProgram = (options: NodeProgramOptions) => Effect<NodeOp, number>`
