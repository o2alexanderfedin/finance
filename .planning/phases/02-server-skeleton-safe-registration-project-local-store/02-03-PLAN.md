Registration (SEC-01 — the flags MUST be present on this, the first, registration):
```
REPO_ROOT="$(pwd)"
claude mcp add finance-mcp -s local -- node --permission \
  --allow-fs-read="$REPO_ROOT" \
  --allow-fs-write="$REPO_ROOT/.cas" \
  "$REPO_ROOT/index.js" "$REPO_ROOT"
```
(`"$REPO_ROOT"` as the trailing arg becomes `options.args[0]` in `fjs/index.f.js`'s `main`,
i.e. the CAS home passed to `financeMcpServer` — see Plan 01.)

Health check:
```
claude mcp get finance-mcp
claude mcp list
```

Live real-client round trip (headless print mode), targeting the read-only `evo_list` tool
(no CAS writes needed, so no risk to the store):
```
claude -p "Call the evo_list tool from the finance-mcp MCP server exactly once, then stop." \
  --allowedTools "mcp__finance-mcp__evo_list" \
  --dangerously-skip-permissions \
  --output-format stream-json --verbose \
  > /tmp/finance-mcp-live.jsonl
```
The exact tool-name prefix Claude Code assigns to a registered MCP server's tools
(`mcp__<server>__<tool>` is the documented convention, but confirm it empirically against the
actual `tool_use` event `name` field in `/tmp/finance-mcp-live.jsonl` before trusting the
`--allowedTools` filter above — if the prefix differs, adjust and re-run) is exactly the kind
of thing the roadmap's "10-minute empirical" framing anticipates needing a look.
