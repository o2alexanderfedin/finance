<!-- Verified exact regex for comma-degrouping (this exact pattern was tested; a naive
     `.replace(/(\d),(?=\d)/g, '')` is WRONG — it drops the digit along with the comma. The
     replacement group must be `'$1'`, not `''`. -->
```
printed.replace(/(\d),(?=\d)/g, '$1')
```
Verified against `'1,234.56'` -> `'1234.56'` -> `parse(2)` -> `123456n`, and against
`'1,234,567.89'` -> `'1234567.89'` -> `123456789n`. A leading/trailing/doubled comma (`',1234'`,
`'1234,'`) is NOT matched by this pattern (the digit-lookahead/lookbehind requires a digit on both
sides), so it survives into `parse`, which then correctly throws — malformed input is not silently
accepted.

<!-- fjs/cas/evo/module.f.js + node_modules/functionalscript/fjs/cas/evo/proof.f.js (pattern to mirror
     for Task 4's same-subject proof — read the real proof.f.js file, this is a condensed pointer). -->
```
import { fileCas } from 'functionalscript/fjs/cas/module.f.js'
import { sha256 } from 'functionalscript/fjs/crypto/sha2/module.f.js'
import { emptyState, virtual } from 'functionalscript/fjs/effects/node/virtual/module.f.js'
import { initEvo, evo } from 'functionalscript/fjs/cas/evo/module.f.js'
import { step } from 'functionalscript/fjs/effects/module.f.js'

const c = fileCas(sha256)('.')
const program = step(initEvo(c), cacheKey => {
  const e = evo(c)(cacheKey)
  return step(e.add({ parents: [], subject: mySubject, snapshot: someHash }), r1 =>
    step(e.add({ parents: [unwrap(r1)], subject: mySubject, snapshot: someHash }), r2 =>
      e.head(mySubject)))
})
const [, heads] = virtual(emptyState)(program)
// heads.length === 1 — one head, not two parallel subjects/histories
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `ocr.fields` (untrusted, vision-model output) -> `convert` -> stored `vnd.fjs.1099int` | The one point in this phase where untrusted printed-string content becomes a typed, semantically-checked money value. |
| `meta` (caller-supplied identity fields) -> `formSubject` -> Evo subject | A caller error here (wrong TIN, wrong tax year) permanently roots a document under the wrong identity — CAS has no delete. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering | `convert` (money boxes) | mitigate | Every box value is round-tripped through `fjs/exact`'s exact decimal parser before being stored as a canonical string; a value that does not parse exactly is not silently coerced (Task 2's `validate`-integration leaf proves the output always passes the typed dialect's own semantic check). |
| T-05-03-02 | Tampering | `convert` (absence handling) | mitigate | DOC-11's absence-preservation is pinned by a proof leaf that was deliberately broken (RED) and reverted (GREEN) per the mutation-test guidance — a regression to "blank decodes as zero" fails `npm test`, not silently. |
| T-05-03-03 | Repudiation | `formSubject` misuse (wrong identity fields supplied) | accept | This phase does not add a confirmation/review step before a subject is derived and committed — out of scope (no computation/UI in this phase); mitigated at the process level by DOC-01's design (subject is content-of-the-form-derived, not artifact-scan-derived, so a wrong TIN reads as a genuinely different, equally permanent, subject — a known, accepted cost of "decided now because it can never be changed"). |
