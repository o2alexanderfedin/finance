  (`['error', string]`) does not change in this plan.

From `node_modules/functionalscript/fjs/effects/module.f.js` (not yet imported in this file —
add to the existing import line from Plan 01):
- `step: (e: Effect<O,T>, f: (t: T) => Effect<Q,R>) => Effect<O|Q,R>` — for a `Do` node, defers:
  returns `{ ...e, continuation: x => step(e.continuation(x), f) }` without calling `f` yet. This
  is what makes a self-referential `const forever = () => step(do_('casRead')('x'), forever)`
  terminate its own *construction* immediately while still describing an infinite chain — `forever`
  is only called again when a runner's loop reaches that continuation, not when `forever()` is
  first evaluated.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| guest effect chain -> `interpret`'s dispatch loop | The chain's length and termination are attacker-controlled (an LLM-generated program can contain a wrong termination condition, deliberately or not). |
| `interpret`'s result -> a future run record's `inputs[]` (Phase 7 consumes this) | The read set must reflect what was actually dispatched; nothing in this phase lets the guest effect supply or override it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-05 | Denial of Service | `interpret`'s dispatch loop over a generated continuation chain | mitigate | `stepBudget` (10,000, named exported constant) bounds the loop; exceeding it returns `error('step budget exceeded: 10000')` instead of looping forever. `stepBudgetBoundsNonTerminatingChain` proves this against a genuinely non-terminating chain, and the proof itself completing (not hanging, not requiring a kill) is the evidence — per ROADMAP.md Phase 3 success criterion 2's "verified by a proof, not by observation." |
| T-03-06 | Repudiation | The read set attached to `interpret`'s result | mitigate | `reads` is appended only inside the loop, only after `match(map)(e)` succeeds — a refused command never reaches the append line, and no code path lets the guest effect write to `reads` directly. `readSetReflectsActualDispatch` proves the returned set matches the actual dispatch sequence, which is what makes a later run record's `inputs[]` (Phase 7) trustworthy without the program's cooperation. |
</threat_model>
