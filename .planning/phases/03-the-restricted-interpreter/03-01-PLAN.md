<objective>
Build `interpret(map)(effect)` — the restricted effect interpreter's dispatch and refusal
reporting half. A guest effect reaches exactly the operations `map` itself owns (fjs 0.41.0's
`match`/`at` already makes this sound at the property-lookup level; EXEC-02 is closed and is not
reimplemented here). Anything `map` does not own is refused as a `Result`-shaped value naming the
operation and the permitted set — never a throw, and never the bare command string `match` itself
throws.

Purpose: this is the security half of Phase 3 (EXEC-01, EXEC-03, EXEC-04) — the whitelist that
reports itself actionably, with a proof suite that pins the six prototype-inherited names AND the
two-step `__defineGetter__` escalation chased all the way to "did a getter actually get
installed", not just a single refused dispatch.
Output: `fjs/exec/module.f.js` exporting `interpret`, with a `proof` tree covering successful
dispatch, all six named refusals, and the two-step escalation. `npm test` and `npx tsc --noEmit`
both green at the end of Task 2.

From `node_modules/functionalscript/fjs/effects/module.f.js` (+ its `.d.ts`):
- `match: (map: OperationMap<O, R>) => (effect: Effect<O1, T>) => MatchResult<O1, T, R>` where
  `MatchResult = readonly ['done', T] | readonly ['cont', R, continuation]`. Looks the handler up
  via `at` (own-property only, never the prototype chain) and does
  `assert(handler !== null, command)` — **the throw, when it happens, is the bare command
  string**: `typeof thrown === 'string'`, not an `Error`, no `.message`.
- `do_: (command: O[0]) => (...payload) => Effect<O, Return<O>>` — builds a single-command `Do`
  node: `{ command, payload, continuation: pure }`.
- `step: (e: Effect<O,T>, f: (t: T) => Effect<Q,R>) => Effect<O|Q,R>` — composes; for a `Do` node
  it defers `f`, calling it later when a runner reaches that node (used only in Plan 02).
- `pure: (v: T) => Effect<never, T>` — an already-computed value, `() => v`.
- `Effect<O,T> = Pure<T> | Do<O,T>`; `Pure<T> = () => T`;
  `Do<O,T> = { command: O[0]; payload: Pr<O,O[0]>[0]; continuation: (out) => Effect<O,T> }`.
- `Operation = readonly [string, (...args) => unknown]`.
- `OperationMap<O,R> = { readonly [K in O[0]]: (...payload: Pr<O,K>[0]) => R }`.
- `Return<O> = Pr<O, O[0]>[1]` — the output type of whichever command actually ran, distributed
  over `O`'s whole command union.

From `node_modules/functionalscript/fjs/asserts/module.f.js`:
- `assert: (v: boolean, msg?: unknown) => asserts v` — throws `msg` (default
  `'assertion failed'`) if `v` is false; narrows `v` to `true` afterward, and TS also narrows any
  boolean *expression* passed as `v` (e.g. `assert(x === 'cont')` narrows `x` in the following
  code, the same way an `if` would).
- `assertEq: (a: T, b: T, msg?) => void` — `===` comparison.

From `node_modules/functionalscript/fjs/types/result/module.f.d.ts`:
- `Result<T,E> = readonly ['ok', T] | readonly ['error', E]`.
- `ok: (value: T) => Ok<T>`; `error: (e: E) => Error<E>`.

House style, from `fjs/server/module.f.js` (read for pattern only — do not import it):

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| guest effect -> `interpret` | The `Effect` tree `interpret` walks is untrusted data — it can originate from an LLM-generated program (Phase 6/7), so its `command` strings and payloads must be treated as attacker-controlled. |
| `interpret` -> `map`'s own-property set | `map` is the whitelist boundary. Whatever becomes an own property of `map` at dispatch time is reachable; whatever is not, is refused. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-01 | Spoofing | `interpret`'s command dispatch (`match(map)(effect)`) | mitigate | fjs 0.41.0's `match` looks the handler up via `at` (`getOwnPropertyDescriptor`-based), never `map[command]` — an attacker-chosen command string that is not literally an own key of `map` cannot resolve to any handler, inherited or otherwise. Verified directly against the installed package by every proof in this plan, not assumed. |
| T-03-02 | Tampering | `map`'s own-property set via `__defineGetter__` | mitigate | The `__defineGetter__` command is itself refused before `Object.prototype.__defineGetter__` is ever invoked as a handler (`assert(handler !== null, command)` throws before the handler-call line runs) — `twoStepDefineGetterEscalation` proves `Object.hasOwn(map, 'fetch')` stays `false` after the attempt, so the getter is never installed and there is no second-hop payload to reach. |
| T-03-03 | Elevation of Privilege | Prototype-inherited members (`constructor`, `toString`, `valueOf`, `hasOwnProperty`) reachable only by a naive `map[command]` dispatcher | mitigate | Same own-property lookup as T-03-01; pinned by four dedicated regression leaves so a downgrade or a hand-rolled dispatcher swapped in later would fail loudly. |
| T-03-04 | Information Disclosure | Dispatch of an unlisted operation such as `fetch` | mitigate (at this layer) | `fetch` is not an own property of `map`, so it is refused before any handler runs. Residual risk — `import()` executing a blob's module body with full Node privileges before any effect is interpreted — is accepted and tracked outside this module (REQUIREMENTS.md "Accepted Risks", SEC-02/SEC-03 in Phase 6); out of this plan's scope by the phase boundary in 03-CONTEXT.md. |
</threat_model>
