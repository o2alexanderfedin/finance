Upstream `fjs/media/module.f.js` (functionalscript 0.43.1), the ENTIRE API this task adopts —
read in full, verbatim:
```typescript
export type DialectEntry = { readonly dialect: string; readonly match: (_: Unknown) => boolean };
export declare const dialectEntry: <T extends Struct>(type: T, extraValidate?: (_: Ts<T>) => boolean) => DialectEntry;
export declare const detect: (dialects: readonly DialectEntry[]) => (bytes: Vec) => DetectMeta;
```
`extraValidate` runs AFTER structural validation, on the dialect's own decoded value, and returns
a plain `boolean` (no error channel). `detect(dialects)(bytes)`: the first entry whose `match`
accepts wins; on no match, falls through to `detectVec`'s ordinary text/binary verdict — `{
length, mime_type, type }`, with `mime_type` set to `application/${matched.dialect}+json` only on
a hit.

The upstream WORKED PRECEDENT (`fjs/media/revision/module.f.js`, verbatim):
```javascript
import { dialectEntry } from '../module.f.js'
const isValidRevision = (r) => { const [tag] = checkReferences(r); return tag === 'ok' }
export const revisionDialect = dialectEntry(revisionSchema, isValidRevision)
```

Every one of this repo's own dialect modules already exports a `schema` object (with a direct
string `dialect` literal via `base()`) and a `checkReferences` returning a `Result` — the EXACT
shape `dialectEntry` needs. `fjs/document/ocr/module.f.js` is the ONE exception: it has no
`checkReferences` at all (only structural `validate`), so call `dialectEntry(ocrSchema)` with NO
second argument for that one (structural-only match, `dialectEntry`'s own documented default).
