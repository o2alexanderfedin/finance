<objective>
Store the Tax Table's band structure as data and its rows as an exact, generated function of the
stored ordinary rate brackets — then diff a sample of generated rows against literals
hand-transcribed directly from Publication 1040 (2025), spanning every band-width region, both
width transitions, Success Criterion 3's own $18,000 MFJ row, and the table's last row. Prove the
diff is not a tautology by mutation: breaking a bracket figure the generator depends on must turn
the diff red.

Purpose: TAX-02 requires the Tax Table to be the *published* table, not something derived from
bracket arithmetic and trusted blindly — and this phase's own central risk (T-08-01, per
08-VALIDATION.md) is a diff whose expected side shares a code path with the generator, which is
exactly the failure mode that let a shipped bug through 185 virtual proofs in Phase 7 (see
07-10-FIX-SUMMARY.md).
Output: `fjs/tax/table/module.f.js` — band structure, generator, row-by-row diff proof, tiling
proof, and the $100,000 refusal boundary.
</objective>

    Define `cumulativeBracketTaxCents`, a pure function
    `(brackets: readonly { ratePercent: number, ceiling: string | undefined }[]) =>
    (incomeCents: bigint) => Rational` implementing the standard marginal-bracket formula in
    exact rationals: walk the ordered bracket list, and for each bracket compute the width of
    income it actually covers (the lesser of its own ceiling and the remaining income, minus the
    previous bracket's ceiling), add `of(bandWidthCents * BigInt(ratePercent))(100n)` to a running
    rational total via `add`, and stop once the whole `incomeCents` has been allocated (the last
    bracket, whose `ceiling` is `undefined`, absorbs all remaining income at its own rate).
    Implement this recursively over the bracket list (an accumulator of remaining income, the
    previous ceiling in cents, and the running `Rational` total) rather than with a mutable loop
    variable, matching this repo's functional style. Never use `Math.round`, `toFixed`, or
    `parseFloat` anywhere in this function.

    Define `generateRow`, `(brackets) => (atLeastCents: bigint) => (widthCents: bigint) =>
    bigint`: computes `midpointCents = atLeastCents + widthCents / 2n` and returns
    `halfUp(cumulativeBracketTaxCents(brackets)(midpointCents))`. Document explicitly, in a
    comment beside this function, that every stored band width in `taxTableBandStructure`
    (500, 1000, 1000, 2500, 5000 cents) is even, so `widthCents / 2n` is always an exact integer
    division with no truncated remainder — this is a documented invariant of the stored data, not
    an assumption; Task 2's tiling proof re-derives each width from the stored `atLeast`/`lessThan`
    pair and can therefore also assert this evenness holds.

    Define `rowFor`, `(taxParamSet: TaxParamSet) => (atLeastCents: bigint) => (widthCents: bigint)
    => Row` where `Row = { atLeastCents: bigint, lessThanCents: bigint, single: bigint,
    marriedFilingJointly: bigint, marriedFilingSeparately: bigint, headOfHousehold: bigint }` —
    one row, four tax columns, mirroring the printed page exactly (Estates & Trusts is excluded;
    it is not a column on Publication 1040's own Tax Table). Compute each column by calling
    `generateRow` with that status's `ordinaryBrackets[status].brackets`.

    Define `lookupTaxTable`, `(taxParamSet: TaxParamSet) => (incomeCents: bigint) => Row`: if
    `incomeCents >= tableUpperBoundCents`, `assert(false, ...)` (via
    `functionalscript/fjs/asserts/module.f.js`'s `assert`, which throws the bare message string —
    never construct or throw an `Error`) with a message naming the $100,000 boundary and
    "use the Tax Computation Worksheet" verbatim, matching Publication 1040's own printed text.
    Otherwise, find which of the 5 `taxTableBandStructure` regions contains `incomeCents`, compute
    that row's own `atLeastCents` by flooring `incomeCents` to the nearest multiple of that
    region's width above the region's own `atLeast`, and call `rowFor` with that `atLeastCents`
    and the region's width.

    Finally, define a narrowed module-scope constant this module's own proof (Task 2) and the
    mutation check (Task 3) both use, defined exactly ONCE — never re-indexed at each call site.
    This project's `tsconfig.json` sets `noUncheckedIndexedAccess: true`, so indexing
    `taxParamsByYear[2025]` yields `TaxParamSet | undefined` even though `2025` is a literal key
    — the open index-signature type `fjs/tax/params/module.f.js` declares does not narrow away on
    its own. Write: `const taxParams2025 = taxParamsByYear[2025]`, immediately followed by
    `assert(taxParams2025 !== undefined, 'expected TY2025 parameters to be present in
    taxParamsByYear')` (`assert` from `functionalscript/fjs/asserts/module.f.js`). Every later
    reference to the year-2025 parameter set anywhere in this module — including Task 2's proof
    — uses `taxParams2025`, never a second `taxParamsByYear[2025]` index. Do NOT use a non-null
    assertion (`taxParamsByYear[2025]!`) or a type cast to silence the compiler here — both are
    banned by AGENTS.md's hard rules; `assert` is the only compliant narrowing path, and it
    throws a bare string, never an `Error` — nothing downstream may branch on `instanceof Error`.
